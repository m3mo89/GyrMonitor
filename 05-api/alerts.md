# Alerts API

## Purpose

Alerts identify cattle requiring attention due to prolonged inactivity or elevated risk.

## GET /alerts

Returns alerts filtered by status, severity or cattle.

| Field | Value |
|---|---|
| Method | `GET` |
| Route | `/api/v1/alerts` |
| Use Case | `GetAlertsUseCase` |
| Roles | `ADMIN`, `FIELD_OPERATOR`, `RESEARCHER` |

### Query Parameters

| Parameter | Type | Description |
|---|---|---|
| `status` | `PENDING` \| `IN_PROGRESS` \| `ATTENDED` | Alert status. |
| `severity` | `LOW` \| `MEDIUM` \| `HIGH` | Alert severity. |
| `cattleId` | UUID | Filter by cattle. |
| `page` | integer | Page number. |
| `pageSize` | integer | Page size. |

### Response 200

```json
{
  "success": true,
  "data": [
    {
      "id": "uuid",
      "cattleId": "uuid",
      "tagNumber": "GYR-023",
      "severity": "HIGH",
      "riskScore": 87.5,
      "status": "PENDING",
      "reason": "Inactividad prolongada",
      "createdAt": "2026-06-20T12:40:00Z"
    }
  ]
}
```

## PATCH /alerts/{id}/status

Updates alert status.

| Field | Value |
|---|---|
| Method | `PATCH` |
| Route | `/api/v1/alerts/{id}/status` |
| Use Case | `AttendAlertUseCase` |
| Roles | `FIELD_OPERATOR`, `ADMIN` |

### Request

```json
{
  "status": "ATTENDED",
  "attendedAt": "2026-06-20T13:10:00Z"
}
```

### Response 200

```json
{
  "success": true,
  "data": {
    "id": "uuid",
    "status": "ATTENDED",
    "attendedAt": "2026-06-20T13:10:00Z"
  }
}
```

## Business Rules

- Alerts are generated by backend rules, not by frontend clients.
- New alerts start as `PENDING`.
- Alert severity is derived from risk analysis.
- Attended alerts must preserve traceability to user and timestamp.
- Status changes must be authorized by role.

## Impact Analysis

Alerts affect:

- Field workflows.
- Dashboard.
- Observations.
- Offline Sync.
- Risk Analysis.
