# OpenSpec Usage

This folder documents how GyrMonitor uses OpenSpec.

It does **not** contain generated proposals, generated changes or generated implementations.

The project owner will create OpenSpec proposals and implementations manually to review design decisions carefully.

## Included Documents

| Document | Purpose |
| --- | --- |
| [workflow.md](workflow.md) | Recommended OpenSpec flow for GyrMonitor. |
| [proposal-checklist.md](proposal-checklist.md) | Checklist before approving a proposal. |
| [implementation-checklist.md](implementation-checklist.md) | Checklist before closing implementation. |
| [review-checklist.md](review-checklist.md) | Review checklist for OpenSpec-related work. |
| [naming-conventions.md](naming-conventions.md) | Naming conventions for manual OpenSpec changes. |
| [best-practices.md](best-practices.md) | Practical guidance for writing proposals. |

## Rule

OpenSpec is a decision process, not an automatic code generator.
